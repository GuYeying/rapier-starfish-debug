## §0 定位与设计原则

rapier-starfish-debug = **Rapier2D 物理适配层**：把 rapier 接进 starfish 的 poll 世界观，
核心交付两块——

1. **物理世界封装**（薄）：生命周期 + 步进 + 逃生口；
2. **通用级 debug 渲染**：物理状态 → 线段流的收集器 + 绘制器，
   通过接口控制**渲染内容**（画什么：碰撞体/接触点/关节/AABB…）与
   **渲染类型**（线宽标志/配色/法线长度…），省去按项目定制渲染代码。

设计原则（"不懒人化"的三条落点）：

- **不复刻 rapier API**：不做 `BodyDesc` 这类平行描述结构（骨架期遗留，
  v1 落地时删除）——rapier 的 `RigidBodyBuilder`/`ColliderBuilder` 本身
  就是构建面，复刻一层 = 双 API 面维护成本 + 表达力损失；
- **逃生口优先**：封装层拿不准的字段一律 `get()` 直通 rapier 原生对象，
  适配层只做"starfish 集成需要的增量"；
- **数据面与绘制面分离**：渲染内容/类型的控制全部落在数据面
  （收集器 + 配置），绘制端保持可替换（§2 定稿）。

## §1 参考案例复盘（rapier_render_test）

该案例（winit + wgpu 0.20 直绘）验证了 rapier 0.36 debug 渲染的本征形态：

```
PhysicsWorld.step()
  → world.debug_render(&mut DebugRenderPipeline, &mut backend)
      backend: DebugRenderBackend::draw_line(object, a, b, color)   ← 唯一回调
  → LineList VBO（每顶点 {pos:[f32;2], color:[f32;4]}）
  → 专用线管线 + 正交相机 uniform（pixels_per_meter 缩放）
```

要点：
- rapier 侧全部控制面 = `DebugRenderStyle`（类型）+ `DebugRenderMode`
  位集（内容：`COLLIDER_SHAPES | CONTACTS | JOINTS | AABBs | SLEEPING …`）；
- 输出是**纯线段原始流**（逐段给起止点 + 颜色），没有 mesh/纹理概念；
- 相机即一个 `mat4` uniform，正交投影 + 米→像素缩放。

结论：适配层的本质工作 = **把这条线段流接到 starfish-render 的绘制面**，
外加物理世界生命周期封装。参考案例的 winit 回调循环不搬——starfish 侧
一律 poll 模型。

## §2 starfish-gfx 够用性分析（定稿）

用户问题：debug 渲染用 gfx 模块是否够用？逐条对照事实：

| 维度 | gfx 现状 | 物理 debug 需求 | 判定 |
|---|---|---|---|
| 顶点格式 | `ShapeVertex{pos:[f32;3], color:[f32;4]}`（28B，可自构） | `pos2+color4` | ✅ 兼容（多 4B/顶点） |
| 线拓扑 | `shape2d::line/polyline/*_outline` 全 LineList 家族 | 纯线段流 | ✅ 同构 |
| 管线 | `pipeline::line_pipeline_2d(camera_bind, mesh, sample_count)` 现成 | 专用线管线 | ✅ 不用自写 wgsl |
| 几何容器 | `Geometry{vertices, indices: Vec<u16>}`（索引恒存在） | 每帧万级动态线段 | ⚠️ u16 上限 65536 顶点 ≈ 2.1 万线段 |
| 动态更新 | `access.write_vertex_buffer(mesh, data)` 可复用缓冲 | 每帧全量重写 | ✅ 无分配压力 |
| 相机 | 管线收 `camera_bind`（布局随 shape.wgsl，Mat4） | 正交 + 米→像素 | ✅ 自建一个 uniform 即可 |
| 批次层 | `BatchTopology::Lines` 在 **starfish-pygame** 层 | — | ❌ 不可依赖（物理层不进 pygame 依赖方向） |

**定稿：数据面自持 + 绘制面 v1 用 gfx 积木。**

- gfx 在功能上够用，v1 不写一行 wgsl：`LineSink`（收集器）→ `Geometry`
  → `shape_mesh`/`write_vertex_buffer` → `line_pipeline_2d`；
- 已知天花板（触发任一即换轨，见下）：① 单帧顶点逼近 u16 上限
  （大碰撞体网格 / chain 细分场景）；② 需要 pos2 精简或自定义线样式管线；
- **换轨点已内建**：顶点收集器 `LineSink` 独立成模块——换 render 直绘
  （自持 line.wgsl + `RenderPipelineBuilder::topology(LineList)`，参考
  案例 §1 形态，预估 ~80 行）时只动 `debug/render.rs`，接口与数据面不动。

## §3 依赖与 feature 定案

```toml
[features]
default = ["2d"]
2d = ["dep:rapier2d"]
3d = ["dep:rapier3d"]        # v1 不点亮（§7）

[dependencies]
rapier2d  = { version = "0.36.1", features = ["debug-render", "parallel"], optional = true }
starfish-render = { path = "../starfish/crates/starfish-render" }   # 硬依赖
starfish-gfx    = { path = "../starfish/crates/starfish-gfx" }      # v1 绘制端（§2）
starfish-std    = { path = "../starfish/crates/starfish-std" }      # debug::console_log 等
glam = { version = "0.33.2", features = ["bytemuck"] }

[dev-dependencies]
starfish-we = { path = "../starfish/crates/starfish-we" }           # 仅示例
```

**we 需求分析（结论：库本体零依赖，不设 feature）**：

- debug 渲染器消费的 render 公共面（`RenderContext` / `RenderResourceAccess`
  / `RenderPass`）**不含 we**——render 的 `we` feature 只是 `Window` 便利
  构造糖；开窗、事件、主循环是宿主（示例/游戏/后续 pygame 层）的职责，
  poll 模型下物理库没有理由感知窗口；
- feature 方案适用于"库内存在可选 we 代码路径"——本库没有这种路径，
  引入空 feature 只会误导（让人以为库内行为随 we 变化）；
- 因此 we 只进 `[dev-dependencies]` 供 `debug_render_demo` 开窗。
  编译期平台白名单等约束由 we 自身治理，与本库无关。

**版本契约**：本库公共接口暴露 wgpu 类型（经 starfish-render），依赖树中
wgpu 必须与 starfish-render 解析到同版本（当前 30.0.1）——路径依赖下
cargo 自动统一；改 git/publish 依赖时须钉住。

**仓库关系**：路径依赖 `../starfish/crates/*` 是同机开发期形态；starfish
为上游（render/gfx/we 演进被动跟随），本仓库不反向进入 starfish workspace
（2026-10-23 已迁出）。

  debug/

## §5 接口草案

```rust
// ── world.rs：薄封装，rapier 原生类型直通 ──
// ⚠️ rapier 0.36 实测：`Vector` 为零泛参具体别名（glamx 路线，Vec2 形态），
// 不可写 `Vector<f32>`；prelude 的 `vector![]` 宏是 nalgebra 遗留陷阱
// （产出 Matrix，与 translation 的 Vec2 形参不符）——一律用 `Vector::new(..)`。
pub struct PhysicsWorld {
    inner: rapier2d::pipeline::PhysicsWorld,   // 0.36 新自包含 World（字段全 pub）
    clock: StepAccumulator,
    sim_time: f32,
}
impl PhysicsWorld {
    pub fn new(gravity: impl Into<Vector>) -> Self;
    /// 逃生口：完整 rapier 面（insert/查询/关节/事件队列…全走这里）
    pub fn get(&mut self) -> &mut rapier2d::pipeline::PhysicsWorld;
    /// 固定步长步进（dt = integration_parameters.dt）
    pub fn step(&mut self);
    /// 实际帧时长 → 固定步长积分器，返回实际步数（上限节流）
    pub fn step_frame(&mut self, real_dt: f32) -> u32;
}

// ── step.rs：固定步长积分器（纯逻辑，无 rapier 依赖，独立单测）──
pub struct StepAccumulator { /* dt / max_steps / accumulated */ }
impl StepAccumulator {
    pub fn new(dt: f32) -> Self;                      // max_steps 默认 5
    pub fn with_limit(dt: f32, max_steps: u32) -> Self;
    pub fn advance(&mut self, real_dt: f32) -> u32;   // 存入真实 dt，返整步数
    pub fn alpha(&self) -> f32;                       // 渲染插值系数（M4 预留）
    pub fn reset(&mut self);
}

// ── debug/mod.rs：渲染内容/类型控制面（v0.3 定稿：直透 rapier
//    DebugRenderPipeline，不另设 options 包装——style 自带按刚体类型
//    配色/休眠乘数等全量字段；pipeline 构造含细分轮廓缓存分配，
//    须持久持有勿每帧重建）──
pub struct DebugDraw { pipeline: DebugRenderPipeline }
impl DebugDraw {
    pub fn new(mode: DebugRenderMode) -> Self;                     // style 默认
    pub fn with_style(mode: DebugRenderMode, style: DebugRenderStyle) -> Self;
    pub fn pipeline(&mut self) -> &mut DebugRenderPipeline;        // style/mode 运行期直改
}
impl Default for DebugDraw { /* COLLIDER_SHAPES | CONTACTS */ }

/// 物理状态 → 线段流（每帧调用；sink 内部 clear + 复用缓冲零分配）
pub fn collect(world: &PhysicsWorld, draw: &mut DebugDraw, sink: &mut LineSink);

// ── debug/sink.rs：独立换轨点 ──
pub struct LineSink { /* Geometry 复用缓冲 + u16 上限守卫 */ }
impl LineSink {
    pub fn new() -> Self;
    pub fn clear(&mut self);
    pub fn is_empty(&self) -> bool;
    pub fn vertex_count(&self) -> usize;
    pub fn line_count(&self) -> usize;
    pub fn geometry(&self) -> &Geometry;
}
impl DebugRenderBackend for LineSink { /* draw_line → HSLA→RGBA → 2 顶点 + 索引对 */ }

// ── debug/render.rs：绘制端（gfx 积木组装）──
pub struct DebugLinesRenderer { /* 线管线 + 相机 uniform/bind + 自持动态 VBO/IBO */ }
impl DebugLinesRenderer {
    /// 管线按表面格式/MSAA 构建（格式随 RenderSurface；借一次
    /// shape_mesh 提取顶点布局）
    pub fn new(access: &RenderResourceAccess, sample_count: u32) -> Self;
    /// 正交相机：世界原点=视口中心 × 米→像素缩放（参考案例 §1 同款语义）
    pub fn set_camera_ortho(&self, access: &RenderResourceAccess,
                            viewport_px: (u32, u32), pixels_per_meter: f32);
    /// 灌顶点 + 编码绘制（调用方持 RenderPass，与其它绘制内容自由合批；
    /// ⚠️ 通道须无深度附件——gfx 2D 线管线深度关闭，wgpu 严格相等校验）
    pub fn draw(&mut self, access: &RenderResourceAccess,
                pass: &mut RenderPass, sink: &LineSink);
}
```

标准用法（lib.rs 门面文档同款）：

```rust
let mut world = PhysicsWorld::new([0.0, -9.81]);
world.get().insert(
    RigidBodyBuilder::fixed().translation(vector![0.0, -3.0]),
    ColliderBuilder::cuboid(5.0, 0.2),
);

let mut sink = LineSink::new();
let mut renderer = DebugLinesRenderer::new(&access, surface.sample_count());
let mut draw = DebugDraw::default();

loop {
    // we poll（宿主职责）…
    world.step_frame(clock_dt);              // 固定步长积分
    collect(&world, &mut draw, &mut sink);
    if surface.begin_frame(CLEAR, 1.0) {
        let mut pass = surface.open_pass();   // 具体入口落地时对齐 render API
        renderer.set_camera_ortho(&access, surface.size(), 50.0);
        renderer.draw(&access, &mut pass, &sink);
        surface.close_pass(pass);
        surface.present();
    }
    next_frame().await;
}
```

> TBD（落地微项）：`open_pass/close_pass` 的实际形态以 render 侧既有
> RenderPass 构造路径为准（command_encoder + surface attachments 组装），
> 不新增 render API——需要 shim 就放本库 `debug/render.rs` 内。

## §6 帧循环集成（时序定约）

poll 模型下一帧的物理时序：

```
poll_event（事件先行，物理不被输入阻塞）
  → clock 取实际 dt → world.step_frame(dt)   [0..n 次 step，n = accumulate(dt/h)]
  → collect(debug)                            [物理后、渲染前，读的是本帧终态]
  → begin_frame → draw(debug) → present
  → next_frame().await
```

- 固定步长积分器与 starfish `time.Clock` 节流哲学一致：**上限节流**
  （实测帧 dt 超过阈值按阈值计，防死亡螺旋——连续追帧最多 N 步/帧）；
- 渲染插值（render interpolation，物理终态与渲染帧间的残差平滑）v1 不做，
  列为 M4 可选项——2D debug 渲染 60Hz 固定步长下残差不可感。

## §7 3D 维度（feature `3d`，2026-10-23 点亮）

- **双维度并存定案（v0.5 取代互斥）**：`2d`/`3d` **可同时开启**——实现
  按 `dim2::` / `dim3::` 命名空间隔离（同名类型并存，各带自己的 rapier
  prelude；共享 `step.rs`/`hsla.rs` 纯逻辑）。单维度：顶层
  `rapier_starfish_debug::prelude` 自动指向唯一维度；双开：按模块路径分别导入
  （`use rapier_starfish_debug::dim2::prelude as p2;`）。默认 `2d`。
- **零转换**：3D `draw_line` 输出 `pos3` 直通 `ShapeVertex.pos3`（2D 侧 z=0
  占位）；hsla 转换、u16 守卫、积分器、DebugDraw/collect 全维度共享；
- **绘制端差异**：`line_pipeline_3d`（深度开启，Depth24Plus）——通道契约
  与 2D **相反**：必须带深度附件（wgpu 严格相等校验）；相机 =
  `set_camera_lookat(eye, target, fov_y, viewport)`（手写 look-at + 透视
  RH/深度 0..1，不触 glam deprecated 投影 API；矩阵单测锚定 NDC 居中与
  深度合法）；
- **实测差异点**：3D 欧拉旋转 = `.rotation(Vector::new(x,y,z))`；胶囊 =
  `capsule_y/capsule_x/capsule_z`（无 2 参 `capsule`）；球轮廓 =
  3 正交大圆 × subdivisions（2D 圆 = subdivisions + 1）；
- 验收示例 `debug_render_demo_3d`（required-features = ["3d"]）：环绕相机
  （A/D 环绕、W/S 距离）+ 同款 1-5 内容位 + 6 睡眠标识；实机冒烟
  ~1020 帧/12s 零校验错误。
